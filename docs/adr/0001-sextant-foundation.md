## Decision
1. **Never self-invent.** Every mechanism and strategy names its source in `docs/manifest.md`. `dangerfile.js`, run by the `source` check, refuses a PR without one, and self-invention is P0 in review.
2. **Compound and self-maintain.** Lessons feed back through PRs, and the harness keeps itself current.
3. **Boundaries, not hooks.** The sandbox is a dev container, gates are GitHub rulesets, and keys are Environment secrets. Zero project hooks.
4. **Landing, amended 2026-11-09 for the public repository.** Squash auto-merge requires `ci`, `source` and `review`, without an up-to-date rule. `ci` runs unprivileged `pull_request` code on GitHub-hosted runners. One default-branch `workflow_run` gate runs Danger through the API, dsh-github, and any required API reviewer; it never checks out or executes PR code and posts statuses on the exact head. Gate, prompt and Danger edits receive an automatic extra other-family API review (owner ruling 2026-11-09), except that a Codex author adds one only when it selects Claude (D-34, 2026-11-10). This replaces the earlier gh-aw/local-runner review path; [Public gate sources](../manifest.md#public-gate).
5. **Orca dispatches, AO repairs, the checks decide (2026-11-08).** Orca ([stablyai/orca](https://github.com/stablyai/orca)@v1.4.251 `a162e08b29b2883b02d8a0dfcc99e26c80b2cfe7`) is the cockpit and the only lane dispatcher. AO ([OrchestratorInc/agent-orchestrator](https://github.com/OrchestratorInc/agent-orchestrator)@v0.14.10 `033d597032e448a0ea16c298350e36b099f74106`) takes only a handed-off PR: `backend/internal/lifecycle/reactions.go` `ApplyPRObservation` returns its failed checks, review comments and merge conflicts to the owning session, on by default per session. AO picks the worker per session with `--harness` (`backend/internal/cli/spawn.go:234-241` at the pin above); which workhorse a session gets is #254 row 10's choice, decided from D3, under the owner's "Muse/Codex as workhorses" (2026-11-08 01:35); the host AO project's default worker is `claude-code`, and the shipped claim path is the exception, creating and spawning Codex today (`deploy/wsl/ao.sh:52,84`; `docs/start.md:33`). Its `claude-agent-acp` chat path stays blocked, and it never merges, reviews or starts work. `ci`, `source` and gh-aw's `review` remain the only gate. Four blind sources, one per family (the DeepSeek, GPT and Google legs, and the earlier Claude study weighted as one leg), screened about 1,656 repositories, deep-scored the same 33 and each put AO first; a blind GPT re-reconcile agreed, conditionally. Nothing beat the three on turning a PR merge-ready, running our runtimes and staying on local worktrees (`orch-convergence-legs/RECONCILE-orchestrators.md` sha256 `0ab1eabb…` §3–§5; `orch-convergence-legs/RECONCILE-gpt.md` `85bdcb4e…` §1.6). Sandboxing is the one gap, a #109 research track, not a component.
6. **Review families and landing standard, amended 2026-11-09.** dsh-github reviews every PR using main's dsh pin and `deepseek-flash` at max. From the third reviewed head only P0 blocks. ## Consequences and residuals
- The read-only binds stop direct edits, not an agent replacing the writable `.git` parent, as upstream's README also says. So the host runs no git or script in a working copy an agent has used.
- A malicious page could trick a no-prompt agent into sending out what is in its sandbox: sign-ins and agent keys, never broker keys. Use low-limit, rotatable keys. Owner accepted.
- Environment secrets reach the local JIT job, so review keys must be low-limit and rotatable; local root can read them. Broker keys stay unavailable to these check runners and the agent sandbox; paper/live broker-key jobs require their separately sanctioned local runner/private network. JIT alone grants no Secrets/devc exception. The live device is chosen at Phase 7, preferring one with no agents.
- In ci, PR code runs as the runner's own user, so it can read that job's one-job runner credentials (the JIT input in its parents' `/proc` environment, the RSA key in the job root) until GitHub de-registers the runner after the job; upstream has no isolating option short of ARC's Kubernetes mode ([runbook](../../deploy/review/README.md#credentials)). The owner accepted it on 2026-11-07 (#201): "Accept + add exit cleanup"; a slot that stops early deletes its registration.
- Producer credential: the lead decided, under the owner's explicit delegation (2026-11-07, verbatim: "please decide with sota convergenced and recommand"), to keep the existing gh login as the JIT producer's credential for now. It predates #201. Every agent session on this host already holds it. With passwordless sudo, no on-host placement hides a credential from agents. Upgrade, when an agent-free host exists: a dedicated GitHub App with only Administration (read and write) and Metadata (read) on this repository ('Authenticating ARC to the GitHub API', read 2026-11-07), minting short-lived installation tokens ('To use the API on behalf of an organization or another user, you should create a GitHub App', 'Keeping your API credentials secure', read 2026-11-07). Rotate the gh token on any suspected exposure. The #138 re-check's reconciliation may supersede this.
- The repository's own docker jobs are main-gated, but a new branch workflow can still request the docker label: GitHub limits runners to selected workflows only through organization or enterprise runner groups. The repository has no collaborator (lead, 2026-11-07). Prerequisite: before any collaborator is added, the docker profile moves to an organization runner group limited to selected workflows, or to an agent-free host ([runbook](../../deploy/review/README.md#two-profiles)). The lead accepted this residual under the owner's delegation (2026-11-07, verbatim: "please decide with sota convergenced and recommand"). The repository has no collaborator. Every writer today is an agent on this host with passwordless sudo, so the docker label gives a writer nothing beyond the host access it already has. The prerequisite above makes it a boundary before any outside writer exists.
- A docker-profile job controls the runner user's daemon, so it can reach that user's files and could replace the daemon socket. It also shares the host's `/tmp`, as gh-aw expects of a runner and its daemon: systemd's `PrivateTmp=` would isolate it but breaks RootlessKit's subordinate-ID mapping. AWF mounts that same `/tmp` into every gh-aw agent sandbox, so an agent reading untrusted PR text can read the host's world-readable `/tmp` files and write into its world-writable directories. The lead accepted, under the owner's delegation (2026-11-07, verbatim: "auto proceed with those sessions actions confirm etc with as you are the lead"), that AWF mounts the daemon's /tmp, which is the host's, read-write into every gh-aw agent sandbox (gh-aw-firewall v0.29.0 system-mounts.ts:29). Measured: about 1,605 world-readable top-level files and 5 world-writable directories; a gitleaks scan found no credential. Limits: the AWF egress allow-list, configured safe outputs only, agent scratch 0700, and the slot's any-depth sweep of subordinate-range entries after every job. The upgrade is an agent-free host. That is the docker profile's trust boundary, held by main-gating. The gh-aw agent never sees the socket: AWF masks it unless DinD is enabled, and gh-aw stages system binaries instead of mounting the runner's filesystem ([runbook](../../deploy/review/README.md#two-profiles)).
- Local JIT removes hosted Actions compute charges, not provider charges: review bills at DeepSeek's, Anthropic's and OpenAI's API rates. Daily usage is intentionally uncapped under ADR-0030 #5; per-review costs and large-review completion remain unmeasured.
- Anyone who can merge to `live` could reach the live key, so `live` needs a promotion record and two-family review.
- **Stale required checks take a new head, not a re-run (2026-11-07).** GitHub: "Required checks must pass on the latest commit SHA. Checks from earlier commits don't satisfy the requirement." ([Troubleshooting required status checks](https://docs.github.com/en/pull-requests/how-tos/merge-and-close-pull-requests/troubleshooting-required-status-checks), read 2026-11-08). A `pull_request_target` re-run replays the original workflow on the original SHA, and a draft toggle re-runs on the same head, so billing-failed runs from before #201, or a `review` check filed under a cancelled suite, keep a head BLOCKED. Landing gives the PR a new head: a merge-forward of `main` with the manifest union driver, `just ci`, one push. Runs are never deleted.
- **Force-cancel is for unresponsive runs only (2026-11-07).** GitHub's REST reference: force-cancel "bypasses conditions that would otherwise cause a workflow execution to continue, such as an always() condition on a job", and "You should only use this endpoint to cancel a workflow run when the workflow run is not responding to" a normal cancel ([workflow runs](https://docs.github.com/en/rest/actions/workflow-runs#force-cancel-a-workflow-run), read 2026-11-08). gh-aw's `always()` conclusion jobs drain by design, even queued behind one another. Landing force-cancels without asking only a conclusion or other `always()` job on a superseded, merged or closed head that has sat QUEUED with no runner while its label's runners took other jobs or none was live, counted from its own first sighting at the head of its group and never from `created_at`, after one pre-read, and logs its run, head and queued-since on #58. Anything else asks the lead.
